## 踩坑（重要）：全新 DB 內建角色無任何權限（RBAC 全掛）
- 症狀：login 後 `user.permissions` 是 `[]` / JWT 無 permission claims → 所有頁面 403、sidebar 全空。
- 根因：M5 把 `DbSeeder` 改成「角色不存在才套 RoleDefaults」，但 4 個內建角色（admin/hr/manager/employee）是由 migration `HasData` 建立的——**角色已存在 → 權限永遠不會被 seed**。因此全新 DB 的 `role_permissions` 是空的。本機 dev DB 就是此狀態（先前 valid 是因為啟動過舊版 seeder 補過）。
- 修法：`HrDbContext.OnModelCreating` 對 `RolePermission` 加 `HasData(PermissionCatalog.RoleDefaults 展開)`（RoleSeedIds 映射 id 1-4）；migration `20260918043400_SeedRolePermissions`。`dotnet ef database update` 後四角色權限恢復（admin 13/hr 11/manager 9/employee 5）。此 HasData 後續不影響 admin UI 編輯（種子只在 migration 執行時寫入一次）。
- **教訓**：全新 DB 驗證 RBAC seed 是否完整；HasData 種子角色時也要把關聯權限一起種，別只靠 DbSeeder「角色不存在才建」的路徑。
